# Input decks of the paper cases

All cases are the PWFA ion-motion setup of `examples/pwfa_ion_motion.in` (Gaussian driver
n_b = 10, sigma_r = 0.3; pinched witness n_b = 1.25e4, sigma_r = 0.01; mobile hydrogen ions;
R = 8, xi step 0.005). The decks are self-contained and generated by `make_decks.py`
(re-run it if the base deck changes). The decks were checked by running them again:
they reproduce the convergence errors of the paper exactly.

**Convention:** the decks and scripts here use the ξ = z − t convention of this version (head of the
box at `xi.max` = 0, the box extends to negative ξ). The paper (QUARZ v1.0.0) uses ξ = t − z, so its
ξ values are the negatives of the ones here, and figures made with these scripts are mirrored in ξ
relative to the published ones (head on the right). To reproduce the published decks and figures
exactly, use QUARZ v1.0.0.

Run: `QUARZ=/path/to/quarz LAUNCH="mpirun -np 4" bash run_paper_cases.sh [groups]`
(groups `conv ref maps evo bench mpi`, default `conv maps evo bench`). Output goes to
`out_<case>/` and `log_<case>.txt` in the current directory; the script prints the wall time and
the mean time per sweep. On CPUs pin the threads (`OMP_PROC_BIND=close OMP_PLACES=cores`); `OMP_PROC_BIND=false` only
in containers with a restricted CPU set.

Convergence runs: `driver.analytic = witness.analytic = 1` (rigid analytic beams), one field
solve (`time.steps = 0`) on xi = 0…7.3. Errors are measured against `conv_ref_s0.03125` in the
witness region with `paper/scripts/errs.py` (kept with the paper sources); in the stretched decks
all three reference steps of the base grid are multiplied by the factor in the name.
Evolution runs: analytic driver, particle witness (2e5), dt = 10. The warnings about unused
driver keys (`emit_n`, `espread`, `nparticles`) in these runs are expected.

## Notes for GPU tests
- One sweep = 1460 slices (1800 for `maps_s1` and the evolution runs); each slice does the plasma push,
  deposit and tridiagonal solves on N radial nodes. With N = 172…512 a slice has too little
  work to fill a GPU; the large-N convergence decks (N = 3700…32000) and `bench_particles_s1`
  (beam push of 6e5 particles every step) are the more telling GPU cases. The plasma has
  4 macro-particles per cell, so the particle count per slice scales with N.
- The tridiagonal solves use parallel cyclic reduction on GPUs (`solver.tridiag = auto`, can be forced to `thomas` or `pcr` for comparison); please compare GPU
  results with a CPU run
  (`validation/cmp_runs.py cpu_dir gpu_dir 1e-8`, round-off differences are expected).
- MPI with several GPUs: one rank per GPU is chosen automatically (`rank within the node mod
  #GPUs`). The pipeline needs at least a few times more sweeps than ranks to be efficient
  (speed-up 1.8 on 2 CPU ranks for 13–25 sweeps), so use the 100-step decks
  (`evo_*`, `bench_particles_s1`) for multi-GPU scaling, not the single-solve decks.
- Report the `sweep … s` lines of the log (time per step, excluding start-up and output).

## AWAKE self-modulation benchmark (Secs. "Self-modulation of a long proton bunch" and "Parallel performance")

Decks by T. C. Wilson (setup of Farmer et al., IPAC'26 TUP3035; units k_p^-1 = 200 um at 7e14 cm^-3):
`awake_uniform.in` (3840 cells) and `awake_stretched.in` (403 cells) produce Fig. fig_awake (fields
at step 150 = 6 m; runs to 12 m); `awake_nodiags.in` is the uniform deck without output, used for
the timings of Table tab:perf. Measured on JUWELS (2 x Xeon Platinum 8168 per node) and JUPITER
(NVIDIA GH200, GPU only; per-sweep times averaged over 50 sweeps, 10 on one core): 1 core 1519 s per sweep, 48 MPI ranks 35 s, 1 GPU 25 s, 16 GPUs 1.8 s per rank.
